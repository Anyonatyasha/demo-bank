# Покупка купона: демо платёжного флоу

Пользователь выбирает купон, оплачивает его на странице «Демо-банка» и возвращается на сайт, где ждёт подтверждения оплаты и получает код купона.

Проект воспроизводит реальную проблему онлайн-платежей. После оплаты банк сразу возвращает пользователя на страницу успеха, а подтверждение (вебхук) присылает серверу позже. Если в этот момент показать «Оплата прошла», можно выдать купон за неоплаченный заказ. Поэтому экран результата не доверяет адресу страницы. Он опрашивает статус платежа, пока не получит ответ от сервера, и корректно обрабатывает отказ банка и случай, когда банк так и не ответил.

React, TypeScript, Vite, React Router. Бэкенд заменён моками в `src/api/paymentApi.ts`, данные хранятся в `localStorage`, поэтому статус заказа сохраняется после перезагрузки страницы.

## Запуск

Нужен Node.js 20.19+ или 22.12+.

```bash
npm install
npm run dev
```

| Команда | Что делает |
| --- | --- |
| `npm run dev` | запуск в режиме разработки |
| `npm run typecheck` | проверка типов TypeScript |
| `npm run lint` | линтер (oxlint) |
| `npm run build` | сборка для продакшена |

Vite при сборке не проверяет типы, поэтому перед коммитом стоит запускать `npm run typecheck`.

## Флоу

1. **`/`: каталог.** «Оплатить» вызывает `createPayment(couponId)`: создаётся заказ со статусом `pending`, возвращается ссылка на оплату. Кнопки блокируются, чтобы не было двойного платежа.
2. **`/bank?orderId=...`: «Демо-банк»** с тремя исходами:
   - **Оплатить успешно**: `confirmByBank(id, 'success')` и сразу редирект на `/payment/success`. Статус сменится на `success` только через 3 с (имитация позднего вебхука).
   - **Отклонить**: `confirmByBank(id, 'failed')` и редирект на `/payment/fail`.
   - **Банк не ответил**: вебхук не придёт, статус остаётся `pending`. Редирект на `/payment/success`, где через 10 попыток показывается таймаут.
3. **`/payment/success?orderId=...`: экран результата.** Хук `usePaymentStatus` опрашивает статус каждые 2 с, максимум 10 попыток:
   - `loading`: «Платёж обрабатывается»;
   - `success`: «Оплата прошла» и код купона;
   - `failed`: ошибка и «Попробовать снова»;
   - `timeout`: «Не удалось подтвердить платёж», кнопки «Проверить снова» и «Написать в поддержку», ссылка на «Мои покупки».
4. **`/orders`: «Мои покупки».** Список всех заказов, новые сверху, загружается через `getOrders()`. У оплаченных показан код купона, у заказов в обработке есть ссылка «Проверить статус», которая ведёт на экран результата. Так купон можно найти, даже если пользователь ушёл со страницы результата или получил таймаут.

## Ключевые решения

- **Попадание на `/payment/success` не доказывает оплату.** URL можно открыть вручную, а вебхук мог ещё не прийти. Результат показывается только по статусу из «бэкенда».
- **Код купона выдаёт «бэкенд»** в момент подтверждения оплаты, а не клиент.
- **Опрос останавливается** на финальном статусе, по лимиту попыток и при уходе со страницы (cleanup в `useEffect`). Ответы, пришедшие после отмены, игнорируются.
- **Статус переживает перезагрузку и закрытие вкладки.** Время вебхука сохраняется в заказе, и если таймер не успел сработать, статус досчитывается при следующем запросе.
- **Обработка вебхука идемпотентна:** завершённый заказ повторно не меняется, второй код купона не генерируется.
- **Строгая типизация.** Статусы заказа и экрана описаны union-типами, поэтому опечатка в статусе — ошибка компиляции. Данные извне (параметры URL, `localStorage`) проверяются на входе: например, страница банка без `orderId` сразу показывает «Заказ не найден», и дальше код работает с гарантированной строкой.

## Структура

```
src/
  types.ts                    типы данных: Coupon, Order, Webhook, статусы
  api/paymentApi.ts           моки: createPayment, getOrderStatus, getOrders, confirmByBank
  hooks/usePaymentStatus.ts   опрос статуса с лимитом попыток
  pages/                      CatalogPage, BankPage, PaymentResultPage, PaymentFailPage, OrdersPage (.tsx)
  components/                 CouponCard, StatusView (.tsx)
  App.tsx                     маршруты (+ страница 404)
  main.tsx                    точка входа
```
